# Reference integration inventory

This inventory separates native SuperDoc calls, demo-owned agent tools, and compatibility workarounds. A native Word field or footnote in the exported file does **not** imply its mutation used a native Document API: several paths below edit OOXML snapshots. Keep these boundaries when extracting modules later.

## Native API usage

The demo uses the SDK's core agent toolkit, inspect/search/read operations, source/citation/field reads, native tracked-change decisions, collaborative document save/replace, browser selections, and `ui.viewport.getRect`. Hocuspocus provides shared document transport. Cursor-based toolbar selections come from the browser API; highlight rectangles come from the native viewport API. Native citation deletion is attempted before its unsupported-context fallback.

## Demo-owned tools

These four tool definitions are added by the demo to the SDK core toolkit. Their underlying document concepts are native Word features; their tool contracts and orchestration are demo code.

| Tool | Responsibility | Owner |
| --- | --- | --- |
| `superdoc_insert_footnote` | Insert a numbered note with exact text at a semantic anchor | `server/src/footnote-tool.js` |
| `superdoc_insert_citation` | Insert a citation to a saved source at a semantic anchor | `server/src/citation-tool.js` |
| `superdoc_references` | List/get/create/update/delete saved reference metadata independently of insertion | `server/src/reference-tool.js` |
| `superdoc_bibliographies` | List/get/create/update/delete bibliography fields, optionally changing style | `server/src/bibliography-tool.js` |

`server/src/document-service.js` owns dispatch, mutation serialization, revision guards, snapshot application, and the fresh reference-library context attached to agent requests. Generic SDK tools retain the SDK dispatch path. Agent instructions route source creation and bibliography requests to these tools and avoid imitation text fallbacks. Bibliography mutations currently require direct Editing mode.

The anchor schema, validation, and recovery instructions live in `server/src/reference-anchor-contract.js`, which has no DOCX or SDK dependencies. Citation and footnote tool definitions use strict decoding with distinct anchor variants; unused optional `afterText` scopes are nullable. Validation reports `INVALID_REFERENCE_ANCHOR`, exact invalid argument paths, accepted examples, and whether inspection is needed. The OOXML resolver/verifier remains in `reference-anchors.js`; cursor-based toolbar insertion keeps its native selection contract.

Anchor-kind instructions explicitly require `sectionEnd` for a named section's final sentence/end. A valid `afterText` anchor can still identify the wrong paragraph for that request; schema validation and position verification alone do not prove that the model chose the user's intended anchor kind. Live export checks remain necessary. After strengthening those instructions and prioritizing the section-end variant, two fresh citation runs used section-end anchors, completed in eight model turns, and preserved all original body paragraphs.

Agent orchestration remains in `server/src/agent.js`. Generic argument parsing/error serialization is in `tool-errors.js`. Generic repeated-failure detection and interruption reports are in `agent-run-progress.js`, with no reference/API dependencies. Reference-specific success and failure descriptions live in `reference-tool-progress.js`. The agent stops after two identical failures for the same tool/arguments/error, even across inspections; revision-only argument changes do not reset that count. Different targets have separate counts. The 12-turn limit is unchanged. Repeated failures, turn exhaustion, and fatal bibliography errors report successful receipts and the last failure instead of reusing intermediate model claims of completion. Placement is called verified only when its receipt includes `resolvedAnchor.verified`.

## Compatibility and placement workarounds

| ID | Problem and demo behavior | Owner / removal condition |
| --- | --- | --- |
| ANCHOR-01 | Models guessed numeric offsets, splitting words and confusing a section's first and last paragraphs. Agent tools now accept an exact `afterText` quote, `sectionEnd` heading, or inspected `paragraphEnd` ID. The host resolves visible UTF-16 coordinates against the current snapshot, follows real heading levels, rejects absent/ambiguous anchors, and returns surrounding text as evidence. | `server/src/reference-anchors.js`; retain deterministic placement even if the transport later becomes native search handles. Current section resolution covers top-level body paragraphs; unsupported or ambiguous scopes fail. |
| ANCHOR-02 | A successful mutation alone is insufficient evidence of placement. Before applying the snapshot, verify the exact citation instruction or footnote ID at the resolved paragraph/offset. The resolver and inserter share one visible-text scanner, excluding deleted text and counting existing markers. | `reference-anchors.js`, `footnote-insert.js`, `document-service.js`; replace only with an equally verified native targeting path. |
| AGENT-RECOVERY-01 | Malformed anchors caused inspect/retry loops until turn exhaustion. Strict anchor variants prevent missing/conflicting fields; structured validation feedback identifies corrections. Generic retry policy stops the second identical failure, and interruption reports use actual successful receipts. Fresh mutation revisions can be reused without redundant inspections when the semantic target is already known. | `reference-anchor-contract.js`, `tool-errors.js`, `agent-run-progress.js`, `reference-tool-progress.js`; demo tool-contract and orchestration safeguards, independent of OOXML compatibility workarounds. |
| REVIEW-01 | SuperDoc 2.18 maps structural footnote insertions to the table caption, despite native `footnote-insertion` semantics. The local adapter sets `Added footnote` only on tracked review records with the exact `footnote insertion` excerpt and erroneous `tableInsert` display type. It preserves IDs, review actions, and document content. | `client/src/components/FootnoteReviewLabels.tsx`, `client/src/footnote-review-labels.ts`; remove when native captions handle footnotes. This is a presentation-model compatibility workaround: `getComment` is public, but writing its `trackedChangeLabel` is not a dedicated supported caption API. DOM observation discovers newly mounted review cards; it does not rewrite document DOM. |
| TYPING-01 | Replacing part of an ordinary word after earlier pending deletions in the same paragraph can split subsequent typing across deletion-side text. In Reviewing mode, before the first plain printable key, normalize a tracked-space selection using the public API's existing visible range and `ui.selection.apply`. The native keyboard handler then owns all typing, formatting, revisions, author identity, and history. Cache the source selection so rapid keys cannot reapply an outdated range. | `client/src/workarounds/tracked-replacement-caret.ts`; thin React lifecycle wiring in `components/TrackedReplacementCaret.tsx`. This is a browser selection remediation using native APIs, not an agent tool or document snapshot edit. Remove after native keyboard replacements retain correct coordinate provenance with earlier revisions. |
| SOURCE-01 | Imported Word source catalogs and opaque metadata must survive SDK round trips. Read/preserve bibliography custom XML, use stable Word tags as source IDs, remap temporary SDK IDs, and preserve unrelated catalogs. Saved source CRUD edits those source records in snapshots. | `server/src/citation-import.js`; retire when native source import/export and stable IDs preserve the same metadata. |
| CITE-01 | Native citation insertion/source lookup rejected valid collaborative contexts or temporary IDs. Insert a Word `CITATION` field referencing the saved tag into a revision-checked snapshot, then render and replace the shared document. | `server/src/citation-insert.js`; retire after native insertion works with persisted source tags in the same collaboration lane. |
| NOTE-01 | Native insertion could fail in paragraphs containing fields, and exports could wrap the footnote part in `document/body`. Insert real footnote XML and relationships while preserving fields; normalize only the recognized erroneous part wrapper. Native numbering and structural review remain native. | `server/src/footnote-insert.js`; retire after native insertion and part export handle the same fixtures. |
| RENDER-01 | Style changes and field display need reliable results. Vendored CSL styles and citeproc render APA/Chicago/MLA caches while preserving native instructions, tracked revisions, and editable field-code display. | `server/src/reference-rendering.js`; retire when native formatting/display supports the same styles and round trips. |
| DELETE-CITE-01 | Keyboard deletion of the last citation character can be rejected while the field remains. Intercept exact citation deletion, try native `citations.remove`, then use the snapshot fallback on `unsupported-context`, including tracked deletion when requested. | `client/src/components/CitationDeletion.tsx`, `server/src/citation-remove.js`; retire when keyboard/native removal handles these contexts. |
| DELETE-BIB-01 | Bibliography text can disappear while its empty field/paragraph persists. Remove the complete generated field and paragraphs; handle backspace/delete on a confirmed empty field in Editing mode, retaining sources, in-text citations, and independent headings. | `client/src/components/BibliographyDeletion.tsx`, `server/src/bibliography-remove.js`; retire when native keyboard/field removal handles the same cases. |
| BIB-READ-01 | SDK field filtering and bibliography IDs could produce false matches or `not found`. Discover fields by their actual `BIBLIOGRAPHY` instruction and address the containing paragraph. | `server/src/document-service.js`; retire after native discovery/addressing works across reloads. |
| BIB-CREATE-01 | Bibliography insertion encountered style-part/ambiguous-paragraph errors. Create the native field in a snapshot, avoiding SDK insertion style resolution. Generated entries inherit the field paragraph's style or document default instead of assuming a `Bibliography` style exists. | `server/src/bibliography-insert.js`, `server/src/reference-rendering.js`; retire after native insertion handles these style contexts. |
| XML-01 | Snapshot serialization can lose original namespace declarations. Preserve document namespaces across round trips. | `server/src/reference-rendering.js`; retire only when exported parts preserve their namespace dependencies. |
| NOTE-LOCATION-01 | Navigation must target superscript body references, rather than the note text near page footers. Scan exported reference locations, then use native selection/viewport geometry for navigation and highlights. | `client/src/footnotes.ts`, `components/FootnoteNavigation.tsx`, `components/FootnoteHighlights.tsx`; retire the scan when native reads expose reliable body-reference anchors. |

Snapshot mutations are serialized and checked against the current revision before application. A stale request fails rather than overwriting concurrent edits. Snapshot replacement is a compatibility transport, not a granular native mutation; preserving native review semantics needs continued round-trip verification.

The typing remediation is intentionally scoped to ready, non-empty, single-paragraph tracked selections whose native visible range has the same length. It leaves Editing/Viewing, collapsed typing, composition, modifier shortcuts, multi-block selections, and selections including deletion-side text on the native path. It neither prevents keyboard events nor buffers/replays characters. It makes no content mutation and schedules no later caret movement. Mount/remount handling follows the public viewport lifecycle; document replacement and unmount clear its state. Unsupported selection application leaves native input in control.

## Verification boundary

Synthetic checks in `server/src/reference-anchors.test.js` cover exact placement, section boundaries, ambiguous anchors, UTF-16/markers, tracked insertion, field rendering, unchanged control text, and cursor-based insertion. `tests/footnote-review-labels.test.mjs` checks the caption guard and unchanged native identity/decision fields.

`reference-anchor-contract.test.js` checks strict variants, nullable normalization, and actionable validation errors. `agent.test.js` exercises the actual agent loop with a scripted model client for corrected retries, repeated failures across inspections, revision changes, malformed arguments, and turn exhaustion. `reference-tool-progress.test.js` checks receipt-only reporting and reference labels. These tests use synthetic metadata and no external API calls.

`tests/tracked-replacement-caret.test.mjs` checks the coordinate conversion, protection against stale repeated ranges during fast typing, guards, and cleanup. A synthetic browser fixture with an earlier pending replacement reproduced the split using trusted pointer selection and keyboard input; the corrected path was exercised at slow and rapid typing rates. Fixture bytes, screenshots, keystroke/selection traces, and exported Word files stay in ignored local artifacts.

Customer reproduction inputs, prompts, exports, traces, and metadata belong in ignored local artifacts. Do not commit them here. The October 19 investigation reproduced both original placement failures through actual Reviewing-mode agent jobs and confirmed corrected anchors and unchanged original body paragraphs in exported DOCX files. The native review API returned `footnote-insertion`; the caption mapping was traced in installed SuperDoc 2.18. Browser automation was unavailable, so the caption adapter still needs a visual browser check.
