# Demo Impact Scorecard

Use this scorecard to decide whether a demo is worth keeping, improving, merging, or retiring.

Apply it to demo apps and examples, including projects generated by Demo Bot.
Demo Bot and its gallery, Slack integration and supporting infrastructure are
tools for creating and delivering demos; they do not receive impact scores.

## How to score

Rate each category from **1 to 5**:

- **1** = weak / not present
- **3** = adequate / mixed
- **5** = strong / clearly excellent

## Score categories

### Relevance

How directly does this demo map to a real customer need or decision?

- **1** = abstract / vanity demo
- **3** = somewhat relevant
- **5** = directly tied to a real customer workflow or blocker

### Clarity

Can someone understand the demo quickly?

- **1** = confusing or too much setup
- **3** = understandable with explanation
- **5** = instantly legible

### Differentiation

Does it show something meaningfully special?

- **1** = generic
- **3** = somewhat distinctive
- **5** = clearly compelling / hard to fake

### Reusability

Can this demo be reused across customers, teams, or conversations?

- **1** = one-off
- **3** = reusable with edits
- **5** = durable canonical example

### Actionability

Does it lead to a next step?

- **1** = interesting only
- **3** = sometimes leads somewhere
- **5** = reliably creates follow-up, decision, or commitment

### Credibility

Is it accurate, supportable, and mature enough to show externally?

- **1** = shaky / experimental
- **3** = mostly solid with caveats
- **5** = safe to use as a proof point

## Overall rating

Add the six scores together for a total out of **30**.

- **26–30** = Canonical / high-value demo
- **20–25** = Strong demo, worth maintaining
- **14–19** = Useful but needs work
- **Below 14** = Candidate to retire or merge

## Outcome fields

Track these separately from the score:

- Views
- Shares
- Repeat views
- Follow-up actions created
- Customer mentions
- Internal reuse
- Outcome achieved

### Outcome achieved options

- Meeting booked
- Eval advanced
- Roadmap decision influenced
- Bug / product gap identified
- Customer adopted the pattern

## Final decision

Choose one:

- **Keep** — strong and reusable
- **Improve** — good core idea, needs polish
- **Merge** — overlaps with another demo
- **Retire** — not worth maintaining

## Repository workflow

Check this rubric when planning a new demo or working on an existing one, and
review it again after verifying the result. Aim for **26–30** and improve the
weakest categories within the requested scope. Prefer a focused, credible
workflow over extra features added only to chase a score.

For a maintained demo, save or update `DEMO_SCORECARD.md` in its directory using
the template below. Include evidence or a short rationale for each score, the
total, the rating band, and the next improvement. Summarize the result in the
handoff or PR description. A score is an assessment, not proof: use honest,
provisional ratings when customer evidence or browser validation is missing.
A numerical rating alone does not establish validated or canonical status.

Keep outcomes separate from scores. Use **Not measured** for unknown metrics
and **Not yet observed** for unconfirmed outcomes; do not invent customer
mentions, usage, commitments, or adoption. Revisit outcomes as evidence arrives.
Record a Keep / Improve / Merge / Retire recommendation; merging or retiring a
demo still requires a task that authorizes that action.
